# 부품 AS 전표 관리

공급사 AS 발송·반환 내역 관리, A4 상하 2부 전표 인쇄, 전체 누적 내역 Excel(.xlsx) 다운로드를 지원합니다. 외부 패키지 없이 Python 3.10 이상에서 실행됩니다.

상단 왼쪽에는 한국 시간(Asia/Seoul) 기준 현재 날짜·요일·시각을 표시하며, 시각은 초 단위로 자동 갱신됩니다. 컴퓨터의 날짜와 시간을 기준으로 동작합니다.

## 버전과 배포 파일

현재 버전은 **V3.0.0**이며 배포 파일명은 **as-manager-windows-V3.0.0.zip**입니다. 이전 버전 배포 파일도 별도로 보관합니다. 화면의 **AS 업무** 옆과 실행창에서 프로그램 버전을 확인할 수 있습니다. 앞으로 수정 사항을 배포할 때마다 버전을 올리고 ZIP 파일명에 같은 버전을 붙입니다. 오류 수정은 `V1.0.1`, 기능 추가는 `V1.1.0`, 큰 변경은 `V2.0.0`처럼 구분합니다. 이전 버전 ZIP은 덮어쓰지 않고 보관합니다.

개발 시 `app.py`의 `APP_VERSION`을 기준으로 화면 표시와 ZIP 파일명을 맞춥니다. 버전은 프로그램 파일에만 적용되며 기존 `data` 폴더와 전표번호는 유지합니다.

## NAS 공유 폴더 / 여러 PC 공동 사용

**실행 파일은 `start-windows.bat` 하나입니다.** 같은 NAS 공유 폴더에서 가장 먼저 실행한 PC가 자동 서버가 되고, 나중에 실행한 PC는 기존 서버로 자동 접속합니다. 서버 PC를 종료한 뒤 다른 PC에서 같은 BAT를 다시 실행하면 NAS의 최신 저장 기록을 이어받아 새 서버가 됩니다. 기존 브라우저의 주소가 자동 변경되는 기능은 아니므로 연결이 끊긴 PC에서는 BAT를 다시 실행하세요.

SQLite는 현재 서버의 로컬 캐시에서 실행하며, 저장 성공 전에 변경 내역을 NAS `.as-shared`에 기록합니다. 완성된 DB 사본과 변경 기록을 함께 보관하므로 서버가 갑자기 종료되어도 NAS에 기록된 자료를 새 서버에서 재생합니다. NAS 저장에 실패하면 저장을 중단하고 입력 창을 유지합니다. 동시에 실행한 PC들이 중복 서버가 되지 않도록 NAS 파일 잠금과 서버 세대 식별을 사용하며, 접속 불가나 시간 초과만으로 잠금을 강제로 해제하지 않습니다.

**V2.0.0을 쓰고 있다면 최초 한 번은 기존 서버 PC에서 이전**해야 최신 로컬 자료를 가져올 수 있습니다. 이후 실행 순서는 자유롭습니다. V1.x의 NAS `data/as.db`도 가져올 수 있습니다. 업데이트 전 모든 기존 서버를 종료하고 `data`·`server-config.json`·`backups`·이미 존재하는 `.as-shared`를 보존하세요. [NAS 자동 공동 사용 안내](NAS-GUIDE.md)에 실행·자료 이전·백업·복원 절차를 설명했습니다.

목록은 25·50·100건씩 읽고 전체 범위에서 검색합니다. 번호·상태·날짜 인덱스, 지원 환경의 부분 검색 색인과 번호 예약을 사용합니다. 매 저장마다 전체 DB를 복사하지 않고 변경한 행만 NAS에 기록합니다. 같은 전표의 동시 수정은 덮어쓰기를 막습니다. 서버 PC는 동작 중 켜 두어야 하며, 모든 서버 후보 PC에 Python과 사내망 통신 허용이 필요합니다. 각 PC는 같은 NAS 폴더를 사용하고, NAS는 SMB 파일 잠금을 지원해야 합니다.

## Windows 실행

1. [Python](https://www.python.org/downloads/) 3.10 이상을 설치합니다.
2. NAS 또는 로컬 프로그램 폴더의 `start-windows.bat`를 더블클릭합니다. 자동으로 서버를 정하거나 기존 서버에 접속합니다. 커맨드 창은 작업표시줄에 최소화되고, 서버가 준비되면 프로그램이 새 브라우저 창으로 열립니다. 기본 브라우저가 Edge·Chrome·Firefox이면 해당 브라우저를 우선 사용하고, 그 외에는 설치된 Edge·Chrome·Firefox 순서로 찾습니다. 지원 브라우저를 찾지 못하면 Windows 기본 브라우저로 열며 이 경우 새 창 동작은 브라우저 설정에 따릅니다. 이미 프로그램이 실행 중이면 서버를 다시 띄우지 않고 새 브라우저 창만 엽니다. 커맨드 창은 작업표시줄에서 다시 열 수 있고, 종료하려면 해당 창에서 Ctrl+C를 누르세요.
3. **보낸이 설정**에서 내 업체명·전화번호·담당자를 입력합니다. 주소와 사업자번호는 입력받지 않습니다.
4. **받는이 관리**에서 AS를 처리하는 업체명과 전화번호를 미리 등록합니다. 전표 작성 시 받는이를 선택하면 전화번호가 자동 입력됩니다. 업체명 또는 전화번호로 검색할 수 있으며 전화번호는 하이픈 없이도 찾을 수 있습니다. 등록 정보를 수정해도 기존 전표의 정보는 유지됩니다.
5. **품명 관리**에서 자주 사용하는 품명을 추가합니다. 품명 관리의 검색창으로 등록된 품명을 찾을 수 있습니다. 전표에서는 모델명 구분 없이 품명 하나를 사용합니다. 부품별 **생산 년월**은 월 선택란에서 연도와 월만 입력합니다(일자 없음). 품명 입력란을 눌러 등록 목록에서 선택하거나 직접 입력하고 시리얼번호·수량·불량 증상을 입력합니다. 수기 품명도 해당 전표·엑셀·인쇄에 저장되며, 자주 쓰는 명칭은 품명 관리에서 별도로 등록하세요. 작성 중에도 **품명 추가/관리** 버튼으로 새 명칭을 등록할 수 있습니다. 등록된 품명을 바꿔도 기존 전표의 명칭은 유지됩니다.
6. **전표 작성**에서 받는이와 부품을 입력하고 저장합니다. 새 전표의 진행상태 기본값은 **발송**이며, 기존 전표를 수정할 때는 저장된 상태를 유지합니다. **접수일 (출고일)**은 기존과 같은 날짜 입력 형식으로 한 번만 입력합니다. 옆에 해당 날짜의 **출고월**(예: 10월)을 자동 표시합니다. 별도의 출고일 입력란은 없습니다. **택배사**와 **출고 송장번호**를 입력할 수 있으며 송장번호의 앞자리 0이 유지됩니다. 택배사·송장번호는 관리 목록과 엑셀에 포함되고 전표 인쇄에서는 제외됩니다. 출고월은 작성 화면과 엑셀에서 확인하며 목록에는 표시하지 않습니다. 공통 날짜는 기존 접수일 위치에 출력됩니다. 출고 정보는 나중에 수정하거나 비워 둘 수 있습니다. 의뢰업체 **GN / 대일**은 선택 사항으로, 둘 다 기본 체크되지 않습니다. 해당 업체가 AS를 의뢰한 건에만 체크하세요. 받는이(AS 처리 업체)와는 별개이며 **GN·대일 중 한 곳만** 선택할 수 있습니다. 한 곳을 선택하면 다른 곳은 비활성화되고, 선택한 곳을 해제하면 다시 선택할 수 있습니다. 기존에 두 곳이 함께 저장된 전표는 원래 기록을 유지하며, 수정할 때 한 곳만 남기거나 모두 해제하고 저장하세요. 목록의 의뢰업체 필터에서 GN·대일·미지정 건을 나눠 볼 수 있습니다. 반환일은 작성 화면에서 입력하지 않습니다.
7. 진행 목록 또는 전체 목록의 **부분완료** 버튼에서 돌아온 품목을 체크하고 이번 반환 수량과 시리얼을 입력한 뒤, 화면 맨 아래의 **입고처리** 목록과 **입고일**을 선택해 저장합니다. 같은 품목 5개 중 2개만 돌아온 경우에도 2개만 기록할 수 있습니다. 남은 품목과 수량은 계속 진행 목록에서 관리합니다. 교환품의 **입고 시리얼번호**는 품목 오른쪽의 파란 입력 칸에서 입력합니다(좁은 화면에서는 품목 아래에 표시). 시리얼 입력 시 해당 품목이 자동 선택됩니다. 입력하면 원래 **출고 시리얼번호**와 별도로 반환 이력에 보관합니다. 여러 개는 쉼표나 줄바꿈으로 구분하세요. 진행 중에는 반환 화면의 기존 이력에서 **입고정보 저장** 버튼으로 입고정보를 수정할 수 있으며 출고 시리얼·반환 수량·반환일은 유지됩니다.
8. **완료** 버튼을 누르면 잔여 품목과 수량 전체가 선택된 입력 화면이 열립니다. **입고 시리얼번호**, 입고처리, 입고일을 확인한 뒤 **완료 저장**을 눌러 반영합니다. 기본 입고일은 오늘이며 바꿀 수 있습니다. 이미 일부가 반환되었다면 잔여 수량만 처리합니다. 입력 중 닫으면 저장되지 않습니다.
9. 전 품목의 전량 반환 시 **완료 목록**으로 자동 이동합니다. 진행·완료·전체 목록을 별도로 볼 수 있으며 완료 목록의 관리 버튼은 **수정 / 전표 출력 / 삭제**입니다. **수정**을 누르면 전표번호·접수일 (출고일)·보낸이 정보·품명·출고 시리얼·수량·생산 년월·증상·입고내역 등을 모두 수정할 수 있습니다. **입고내역 수정**에서 입고 시리얼·입고수량·입고일·입고처리를 각각 변경하고, 내역을 추가·삭제할 수 있습니다. 입고 시리얼 입력칸은 높이가 고정되어 있으며 드래그로 늘어나지 않습니다. 품목을 삭제하면 해당 품목의 입고내역도 함께 제외되므로 저장 전에 확인하세요. 입고수량을 바꾸면 진행상태가 자동 갱신됩니다.
10. 전표 출력 → 프린터로 출력에서 A4, 세로, 배율 100%, 여백 기본(프로그램 지정 12mm)을 사용하고 브라우저 머리글/바닥글은 해제합니다. 받는이 보관용은 위쪽, 보낸이 보관용은 아래쪽입니다. 전화번호는 출력되며 주소·사업자번호는 출력되지 않습니다. 날짜 제목은 **접수일 (출고일)**로 출력됩니다. 의뢰업체와 출고 시리얼번호는 포함되며 **생산 년월·입고 시리얼번호·입고처리·입고일·비고는 인쇄 및 인쇄 미리보기에서 제외**됩니다. 해당 항목의 입력·저장·엑셀 출력은 그대로 유지됩니다.
11. 엑셀로 변환는 필터와 관계없이 저장된 전체 전표의 품목별 행을 내려받습니다. 기존 엑셀 파일을 직접 수정하는 방식이 아니라 데이터베이스에 누적한 뒤 최신 엑셀을 생성합니다. 전화번호와 품명별 반환이력 열은 제외합니다. **전표번호 → 접수일 (출고일) → 출고월 → 택배사 → 출고 송장번호** 순서로 표시됩니다. 접수일과 별도 출고일을 중복 표시하지 않습니다. 출고 시리얼 바로 옆에 입고 시리얼을 표시하며 변경 시리얼이 없으면 빈칸입니다. 그 다음은 **비고 → M/B 수리내역서 작성** 순서입니다. 비고는 전표 작성 시 입력한 내용이며, 수리내역서는 해당 품목을 반환 처리할 때 입력한 내용을 누적합니다. 마지막 두 열은 **입고처리 → 입고일** 순서로, 해당 품명의 최근 입고 기록을 표시합니다.

진행상태는 **부분완료 / 완료**로 표시하며 목록·상태 필터·수정 화면·인쇄·엑셀에 동일하게 적용합니다. 기존 기록의 상태와 완료 목록 분류는 그대로 이어집니다.

목록 열 제목은 **번호 / 구분 / 송장번호**로 간단히 표시합니다. 번호 아래의 접수일과 송장번호 위의 택배사명은 그대로 표시하며, 의뢰업체가 없으면 미지정 안내 문구 없이 구분만 표시합니다. 진행 전표의 관리 버튼은 첫 줄 **부분완료 / 완료**, 둘째 줄 **수정 / 전표 출력 / 삭제** 순서입니다.

## 전표 검색

진행·완료·전체 목록의 검색창에서 **출고/입고 시리얼번호, 송장번호, 받는이, 품명, QR코드번호, 전표번호**로 검색합니다. 검색 대상이 **전체 항목**이면 비고·불량 증상·M/B 수리내용·입고처리·택배사·보낸이·전화번호·담당자·날짜·의뢰업체·진행상태도 함께 찾습니다. 목록에서 생략된 두 번째 이후 품목과 모든 입고 이력의 시리얼도 검색합니다.

- **검색 대상**을 선택하면 해당 항목 안에서만 찾습니다. 출고·입고 시리얼을 함께 또는 각각 선택할 수 있습니다.
- 번호의 앞자리 0은 유지하며 일부만 입력해도 검색됩니다. 영문 대소문자, 전각/반각 문자, 공백·하이픈은 구분하지 않습니다. 예를 들어 `AB-001 234`는 `ab001234`로 찾을 수 있습니다.
- 여러 단어는 공백으로 구분하며 **모든 단어를 포함한 전표**만 표시합니다. 전체 항목에서 `받는업체 DDR5 001234`를 입력하면 받는이·품명·번호 조건을 함께 적용합니다. 같은 전표 안의 서로 다른 품목에 해당 단어가 있어도 검색됩니다.
- 검색어를 입력하면 **전체 목록**으로 자동 이동해 진행·완료 전표를 함께 찾습니다. 진행·완료 목록에서 검색을 시작하면 상태 필터도 모든 상태로 바뀝니다. 의뢰업체 필터는 유지되며, 검색 후 목록·의뢰업체·상태 필터를 선택해 결과를 좁힐 수 있습니다. 검색어를 지우면 전체 목록에 머무르고, 다른 목록을 선택한 상태에서 검색어가 비어 있으면 자동 이동하지 않습니다. **초기화**는 검색어·검색 대상·의뢰업체·상태 필터를 지우고 현재 목록은 유지합니다.
- 검색은 목록만 바꾸며 저장된 데이터와 전체 엑셀 다운로드에는 영향을 주지 않습니다.

## 엑셀 보고서와 그래프

상단 **엑셀로 변환**을 누르면 화면 필터와 관계없이 전체 저장 내역으로 `AS-report-V3.0.0.xlsx`를 만듭니다. 파일을 열면 **AS 보고서** 시트가 먼저 표시됩니다. 외부 패키지 설치나 인터넷 연결은 필요하지 않습니다.

- **AS 보고서:** 총 발송·입고·미입고 수량, 평균 입고 소요일, 전표 수와 수량 기준 입고율. 월별 발송/입고 막대그래프, 월별 평균 소요일 꺾은선그래프, 미입고 경과일 분포와 입고처리 유형 도넛 그래프를 제공합니다.
- **월별 입출고:** 연도와 월별 발송 전표 수·발송 수량·입고 수량·월말 미입고 수량·평균 소요일·28일 초과 입고 수량을 보여 줍니다. 자료가 없는 중간 월도 0으로 표시합니다. 그래프는 최근 24개월, 표는 전체 기간입니다.
- **업체별 현황:** 받는이와 의뢰업체별 발송·입고·미입고 수량, 평균 소요일, 28일을 초과한 미입고 수량을 비교합니다. 두 분류는 각각 전체 수량을 집계하므로 서로 더하지 않습니다. 과거 GN·대일 동시 지정 건은 하나의 `GN · 대일` 분류로 보존하여 중복 집계를 막습니다.
- **입고 상세:** 부분 입고를 포함한 입고 건마다 발송일·입고일·수량·경과일수·입고처리·수리내용을 표시합니다.
- **AS 누적내역:** 기존 전체 품목별 원본 내역과 열 순서를 유지합니다. 수량·반환수량·미반환수량·경과일수는 계산 가능한 숫자 셀입니다. 전표번호·시리얼·QR번호는 문자로 보관해 앞자리 0을 유지합니다.

월별 발송은 **접수일 (출고일)**의 월, 월별 입고는 **각 입고일**의 월로 집계합니다. 일부가 1월에, 나머지가 2월에 입고되면 수량을 각각 해당 월에 넣습니다. **평균 입고 소요일 = Σ(입고수량 × 발송일부터 해당 입고일까지의 일수) ÷ 총 입고수량**입니다. 아직 입고되지 않은 수량은 평균에서 제외하고 미입고 현황에서 따로 관리합니다. 입고가 없는 평균은 0일로 표시하지 않고 빈칸입니다. 경과일 분포는 미입고 제품 수량 기준 `0~7 / 8~14 / 15~21 / 22~28 / 29일 이상`입니다.

그래프는 엑셀에서 편집할 수 있는 차트이며 원본 집계값은 각 시트에 포함됩니다. 입고처리 유형이 많으면 그래프에는 상위 7개와 나머지 합계를 표시하고, 보고서 아래 집계표에는 모든 유형을 보관합니다. 입고처리 선택 목록용 숨김 시트도 유지됩니다. 자료가 없어도 0건 보고서를 생성합니다.

보고서는 **변환한 시점의 저장 자료**를 기준으로 만듭니다. 프로그램에서 내용을 바꾼 후 다시 변환하면 보고서가 갱신됩니다. 엑셀에서 원본 행을 직접 수정한 내용은 프로그램에 반영되거나 보고서 집계표를 자동으로 재작성하지 않습니다. 그래프 모양과 집계표는 엑셀 안에서 편집할 수 있습니다.

## 바코드 스캐너와 GN QR코드

전표 작성·수정 화면에서 **출고 시리얼번호**를 스캔한 뒤 Enter 또는 Tab을 보내면 전표를 저장하지 않고 다음 칸으로 이동합니다. **일반 전표는 출고 시리얼 → 수량**, **GN 선택 전표는 출고 시리얼 → QR코드번호 → 수량** 순서입니다. 수량에서 Enter를 눌러도 전표가 저장되지 않으며, 저장은 **전표 저장** 버튼을 눌러 완료하세요. 키보드 입력 방식의 스캐너를 사용하고 종료 문자를 Enter 또는 Tab으로 설정하세요. Shift+Tab은 일반적인 이전 칸 이동을 유지합니다.

**GN**을 선택하면 각 품목의 출고 시리얼 바로 오른쪽에 **QR코드번호** 칸이 나타납니다. 앞자리 0과 영문·기호를 유지하며 최대 500자입니다. 대일만 선택하거나 의뢰업체를 선택하지 않으면 QR 칸을 숨깁니다. GN 선택을 해제해도 이미 입력한 QR번호는 보존되며 다시 선택하면 확인할 수 있습니다. 새 전표에는 이전 QR번호가 남지 않습니다.

QR번호는 전표·반환 처리·수정 후에도 저장되며 엑셀의 **M/B 수리내역서 작성 다음 열**에 포함됩니다. 기존 **출고 시리얼 → 입고 시리얼 → 비고 → M/B 수리내역서 작성** 순서는 유지합니다. QR번호는 A4 전표에는 인쇄하지 않습니다.

## 전표 삭제

진행·완료·전체 목록의 **삭제** 버튼으로 해당 전표를 삭제할 수 있습니다. 확인 창에서 전표번호·받는이·날짜·상태를 확인하고 **전표 삭제**를 누르세요. **취소 / 닫기 / Esc**는 삭제하지 않습니다. 삭제하면 전표의 품목·반환 이력·M/B 수리내역서가 함께 제거되며 복구 기능은 없습니다. 삭제 전 필요한 데이터는 `data` 폴더로 백업하세요.

삭제한 전표는 목록·통계·새 엑셀에서 제외됩니다. 이미 내려받은 엑셀과 등록된 받는이·품명은 그대로 유지됩니다. 삭제한 표준 전표번호의 순번은 다시 사용하지 않습니다. 다른 창에서 전표가 수정되었다면 삭제를 막으므로 목록을 새로고침하고 최신 내용을 다시 확인하세요.

## M/B 수리내역서 작성

**부분완료 / 완료** 화면 맨 아래의 이번 입고처리 영역에서 **M/B 수리내역서 작성** 입력란에 수리 내용을 직접 적습니다. 선택 사항이며 최대 2000자, 여러 줄 입력이 가능합니다. 이번에 선택해 반환하는 품목에만 저장되며, 전량 반환은 남은 품목 전체에 적용합니다. 다음 반환 때 입력란은 빈칸으로 시작하므로 이전 내용을 새 품목에 잘못 저장하지 않습니다. 여러 번 나누어 반환한 품목의 내용은 엑셀에서 줄바꿈으로 누적합니다.

진행 중에는 반환 화면의 기존 이력에서 수리내역을 고친 뒤 **입고정보 저장**을 누르세요. 전표 수정 화면의 **입고내역 수정**에서도 품목별·입고내역별 내용을 고치거나 비울 수 있습니다. 엑셀 열 순서는 **출고 시리얼번호 → 입고 시리얼번호 → 비고 → M/B 수리내역서 작성**이며, 입력하지 않은 수리내역서는 빈칸입니다. 수리내역서 내용은 A4 전표에는 인쇄하지 않습니다. 기존 저장 내역은 유지되며 별도 데이터 이전 작업은 필요 없습니다.

## 완료 목록의 시리얼 변경 표시

반환 완료된 전표는 품명 아래에 **시리얼 변경 · N품목** 표시가 나타납니다. 표시를 누르면 변경된 품목별 **품명 / 출고 시리얼 / 입고 시리얼**을 펼쳐 확인할 수 있습니다. 완료 목록과 전체 목록의 완료 전표에 적용되며, 일부만 반환되어 진행 중인 전표에는 표시하지 않습니다.

출고·입고 시리얼이 모두 입력된 품목을 비교하며, 입고 번호 중 기존 출고 번호와 다른 번호가 있는 경우에 표시합니다. 쉼표·줄바꿈으로 구분한 여러 번호는 순서나 앞뒤 공백이 달라도 동일 번호로 판단하고, 번호의 앞자리 0과 대소문자는 유지합니다. 출고 또는 입고 번호가 비어 있거나 동일 번호로 입고되었다면 변경 표시를 하지 않습니다. 수정 화면에서 번호를 고쳐 저장하면 표시도 갱신됩니다. 전표 인쇄에는 입고 시리얼과 변경 표시를 넣지 않으며 엑셀의 출고·입고 시리얼 열은 그대로 유지합니다.

## 송장 조회

**진행 목록**의 **송장번호** 열 아래 **송장 조회 ↗**를 누르면 저장된 번호로 택배사 공식 배송 조회 페이지를 새 창에서 엽니다. 전체 목록에서도 진행 중인 전표에 표시됩니다. CJ대한통운·한진택배·롯데택배·우체국택배·로젠택배를 지원하며, `CJ`, `대한통운`, `한진`, `롯데`, `우체국`, `로젠`처럼 입력한 기존 택배사도 인식합니다. 전표 입력의 택배사 칸에서 추천 목록을 선택하거나 직접 입력할 수 있습니다.

택배사가 비어 있거나 인식되지 않으면 조회할 택배사를 선택하는 창이 열립니다. 이 선택은 조회에만 적용되며 저장된 전표는 바꾸지 않습니다. 지원 목록에 없는 택배사는 해당 업체 홈페이지에서 조회하세요. 송장번호 미등록 시 **수정**에서 입력하세요. 조회 시 하이픈·공백만 제거하고 앞자리 0은 유지합니다. 배송 정보는 택배사 사이트에서 확인하며 프로그램에 자동 저장되지 않습니다. 택배사 사이트 접속에는 인터넷이 필요하며, 조회 결과는 택배사 등록 상태와 사이트 운영 여부에 따라 달라집니다.

## 전표번호와 입고처리

새 전표번호는 접수일 기준 `YYMMDD-순번`입니다. 예를 들어 2026년 10월 19일은 `261019-01`, `261019-02` 순서이며 날짜가 달라지면 다시 `01`부터 시작합니다. 이미 발행된 전표번호는 유지하며 같은 접수일의 기존 전표 수를 포함해 다음 순번을 부여합니다. 접수일을 바꿔도 번호를 자동 재발행하지 않으며, 수정 화면에서 전표번호를 직접 변경할 수 있습니다. 중복 번호는 저장되지 않습니다.

입고처리는 사용자가 직접 목록을 관리합니다. **상단 엑셀로 변환 바로 앞** 또는 **부분완료·완료 화면 맨 아래**의 **입고처리 목록관리** 버튼에서 항목을 추가·수정·삭제하세요. 최초에는 수리 / 교환 / 정상 판정 / 수리 불가 / 반송 / 기타를 제공하며, 모두 수정하거나 삭제할 수 있습니다. 모든 항목을 삭제해도 자동으로 다시 생기지 않습니다. 항목은 줄바꿈 없이 최대 60자입니다. 반환·전량 반환 화면의 **맨 아래(저장 버튼 바로 위)**에서 등록한 항목을 선택하며 미선택도 가능합니다. 진행 중인 전표의 반환 화면에 있는 기존 이력 선택란도 각 이력 맨 아래에 있습니다. 목록의 이름을 바꾸거나 삭제해도 이미 저장된 입고 기록의 명칭은 바뀌지 않습니다. 과거에 수기로 입력한 처리 내용은 유지됩니다. 새로 다운로드한 엑셀의 입고처리 셀에도 동일한 사용자 드롭다운 목록이 들어갑니다. 쉼표·따옴표가 포함된 항목이나 긴 목록도 사용할 수 있습니다. 엑셀에서 변경한 값은 해당 파일에만 저장되므로 프로그램 기록을 바꾸려면 프로그램의 입고정보를 수정하세요.

부분 반환 시 품명별 입고처리와 입고일은 각각 해당 품명이 입고된 최근 기록을 표시합니다. 상세 반환 이력은 프로그램에 계속 보관되며 엑셀에는 내보내지 않습니다. 전화번호는 A4 전표에는 기존처럼 표시하지만 엑셀에서는 제외합니다.

## 경과일수

진행 중인 전표의 경과일수는 **0~7일 흰색 / 8~14일 노란색 / 15~21일 주황색 / 22일 이상 빨간색** 배경으로 표시합니다. 29일 이후도 빨간색을 유지합니다. 전체 목록에서도 진행 중인 전표에 동일하게 적용하고, 반환 완료된 전표의 경과일수에는 색상을 적용하지 않습니다.

목록의 경과일수는 **접수일 (출고일)부터 오늘까지**이며, 전량 반환 완료된 전표는 **최종 입고일까지** 계산한 값으로 고정됩니다. 당일은 0일이며 대한민국 날짜 기준으로 계산합니다. 화면을 새로고침하거나 엑셀을 다운로드할 때 다시 계산됩니다.

엑셀에는 품명별 **경과일수**가 포함됩니다. 해당 품명의 수량이 모두 입고되었다면 그 품명의 최종 입고일까지, 미입고 수량이 남았다면 오늘까지 계산합니다. 따라서 부분 반환된 전표에서도 먼저 전량 입고된 품명의 경과일수는 더 늘어나지 않습니다. 접수일이나 입고일을 수정하면 기간도 다시 계산됩니다.

## 터미널 실행

```sh
cd /workspace/codex
python3 app.py
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 종료는 실행창에서 Ctrl+C입니다. `PORT`로 포트, `AS_DATA_DIR`로 데이터 폴더를 변경할 수 있습니다. 기본은 로컬 컴퓨터에서만 접속 가능합니다. 로그인 기능이 없으므로 인터넷에 직접 노출하지 마세요.

## 저장과 백업

전표, 업체 설정, 사용자 입고처리 목록은 `data/as.db`에 저장됩니다. 자동 공동 사용의 기준 자료는 NAS `.as-shared`이며 SQLite 작업 파일은 현재 서버의 로컬 캐시에 있습니다. NAS의 이전 `data`는 최초 가져오기 이후 갱신되지 않습니다. 실행 중 백업은 상단 **데이터 백업**으로 받거나 자동 백업을 사용하세요. 폴더를 직접 복사하려면 서버를 종료한 뒤 전체 데이터 폴더를 복사하세요. 엑셀 파일에는 업체 설정 전체가 포함되지 않아 데이터베이스 백업을 대신하지 않습니다. 전표에는 저장 당시 내 업체 정보가 보관되어 이후 업체 설정을 바꿔도 기존 전표는 유지됩니다. 받는이는 AS 처리 업체, 보낸이는 내 업체입니다. 접수일과 별개인 반환일을 여러 차례 기록할 수 있습니다. 반환 완료된 전표도 모든 입력 항목을 수정할 수 있습니다. 입고수량은 출고수량 이하, 입고일은 접수일 (출고일) 이후여야 하며 진행상태도 입고수량과 일치해야 합니다. 수정을 취소하면 저장되지 않습니다. 반환일은 접수일보다 빠를 수 없고, 미반환 수량을 초과하는 반환이나 중복 요청은 저장되지 않습니다.

한 전표에 최대 8개 품목을 기록합니다. 긴 품명·시리얼·불량 증상은 자동 줄바꿈합니다. 내용이 많으면 각 보관용 전표를 A4 반쪽 안에 들어가도록 자동 축소합니다. 인쇄 미리보기에서 1페이지인지 확인하세요. 프린터 설정도 A4·세로·배율 100%로 맞추고 사용자 지정 확대 배율이나 큰 여백은 해제하세요. 엑셀 가져오기, 사용자별 접근권한 기능은 포함하지 않습니다.

## 기존 버전에서 업데이트

프로그램을 종료하고 `data` 폴더를 먼저 백업하세요. 새 ZIP의 프로그램 파일 전체(`auto_server.py`·`storage.py`·`launcher.py`·`excel_report.py` 포함)를 기존 폴더에 덮어쓰고 `data` 폴더는 유지한 뒤 다시 실행하세요. 실행 중이던 서버도 종료 후 재시작해야 새 기능이 적용됩니다. NAS 공동 사용은 [NAS-GUIDE.md](NAS-GUIDE.md)의 자동 이전 절차를 확인하고 `.as-shared`·기존 `server-config.json`·데이터 폴더를 보존하세요. V2.0.0에서의 최초 이전은 기존 서버 PC에서 실행하세요. 기존 전표의 업체는 받는이 목록으로 이어집니다. 최초 품명 목록을 불러올 때 기존 전표의 품목명과 모델명을 하나의 품명으로 합쳐 자동 등록합니다. 기존 반환 이력도 유지됩니다. 브라우저에서 Ctrl+F5로 화면을 새로고침하세요. 기존 반환완료 전표는 원래 반환일의 전량 반환 이력으로 인식하며 완료 목록에서 확인할 수 있습니다. 데이터 파일을 새로 만들 필요가 없습니다.

자동 테스트는 완료 전표 전체 수정·수량 및 날짜 검증·접수일 기반 월 계산·진행/완료 및 품명별 경과일수, 사용자 입고처리 목록 추가·수정·삭제·기록 보존·빈 목록 유지·긴 엑셀 드롭다운, 날짜별 전표 순번·동시 발행 중복 방지·엑셀 열 순서 및 드롭다운·품명별 입고처리와 입고일, 교환 입고 시리얼과 이력 수정, GN/대일 선택·생산 년월·택배사 저장, 수기 품명 저장·반환·엑셀 보존과 받는이·품명 등록 및 수정, 기존 모델명 통합과 전표 호환, 출고 월 계산·송장번호 보존, 일부 품목/일부 수량 반환, 전량 반환, 반환 이력 보존, 초과·중복·동시 반환 차단, 엑셀 이력 출력을 검증합니다.

## 인쇄 검증 (개발용 선택 사항)

Playwright, Chromium, Poppler(`pdfinfo`, `pdftotext`)가 있는 개발 환경에서는 `node tests/test_print.cjs`로 인쇄 회귀 검증을, `node tests/test_workflow.cjs`로 화면 통합 검증을, `node tests/test_network.cjs`로 두 브라우저의 공동 사용·페이지 이동·수정 충돌·최신 검색 결과를 검증합니다. 별도 Chromium 실행 파일을 사용하려면 `CHROMIUM_PATH`를 지정합니다. 이 도구들은 일반 프로그램 실행에 필요하지 않습니다.

일반 전표, 긴 내용의 최대 8품목 전표, 좁은 브라우저 창에서 A4 한 페이지·보관용 두 부·마지막 품목과 서명란 보존·출력 여백 내 텍스트 배치와 별도 출고일·출고월·송장번호·주소·사업자번호·모델명·생산 년월·입고 시리얼번호·입고처리·입고일·비고 항목의 인쇄 제외와 접수일 (출고일) 제목를 확인합니다. 화면 통합 검증은 전표 검색 대상별 일치·번호 정규화·다중 검색어·후속 품목과 입고 이력 검색·목록 및 필터 조합·초기화·좁은 화면 배치, 받는이/품명 검색·검색 결과 수정, 품명 선택과 직접 입력, 출고 월 변경, 저장 후 유지, 부분·전량 반환과 송장 조회 링크·택배사 선택·누락 및 잘못된 번호 처리를 포함합니다. 송장 조회 검증은 외부 페이지 요청을 가로채 연결 주소와 새 창 동작을 확인하며 실제 배송 결과는 검증하지 않습니다. 실제 프린터 드라이버의 설정은 출력 화면에서 별도로 확인하세요.

대량 자료 성능 검증(시험 DB만 사용): `python tests/benchmark_storage.py --records 10000`. 페이지 조회는 요청한 건수만 정규화하는지, 번호 검사는 인덱스를 사용하는지 자동 검증합니다. Python 3.10 이상을 지원하며 검색 가속을 위해 Python 3.12 이상을 권장합니다. FTS5 trigram이 없는 SQLite에서도 일반 문자 검색과 페이지 조회로 동작합니다.

자동 서버 전용 검증: `python -m unittest discover -s tests -p test_auto_server.py -v`. 세 프로세스 동시 실행·갑작스러운 서버 종료와 재생·NAS 실패 시 롤백·서버 세대 변경에 따른 쓰기 차단을 검증합니다. 배포 ZIP에는 실행용 BAT 하나만 포함합니다.
